# 变更包：三模块任务管理架构重构

## 1. 变更动机

用户确认当前六区架构不符合实际使用方式。工作台、需求中心、成果验收和独立样品管理暂不需要；专题规划、人工分配和多个编辑入口也造成了职责重复。系统应收敛为资源维护、任务全量编辑台和执行中心三个一级模块。

## 2. 当前基线

当前唯一 active 基线为 BL-005。BL-005 仍以 V4 六区专题工作区、专题来源小组、样品池、连续任务排序和成果验收设计为有效基线；本变更只形成 V5 proposed 设计，不改变 BL-005 的激活状态。

## 3. 用户确认的边界

- 第一块为资源维护，维护来源小组、测控成员、制冷机和数据维护；不维护联系人。
- 第二块为任务全量编辑台，使用“专题一级、任务二级”的可展开/收起树形结构；专题支持新增、修改、删除；任务所有业务属性集中编辑。
- 第三块为执行中心，核心是甘特图、成员负载、任务整体时间修改和成员在任务中的时间修改。
- 不建设独立工作台、需求中心、样品管理和成果验收模块。
- 不保留负责人/参与成员拆分、每人工时、任务顺序、前置任务、联系人、项目/课题标签和成果提交字段。
- 任务状态为等待样品、样品交付延期、正在测试、测试延期、已完成；正在测试和已完成由人切换，样品交付延期和测试延期按时间规则计算。

## 4. 影响分析

| 影响域 | 影响 | 处理 |
| --- | --- | --- |
| 信息架构 | 六个一级区域替换为三个一级模块 | V5 需求、总体设计和详设统一描述 |
| 任务事实 | 来源小组成为任务属性；专题仅保留名称、目的、状态、备注 | 后续实现需增加任务来源小组字段并保留历史兼容 |
| 样品关系 | 样品在任务编辑器中维护，不再独立成一级入口 | 保留样品规划、ETA、到样和任务关联 |
| 成员关系 | 只保留任务参与成员，不保留负责人和工时 | 成员日期仍由执行中心按任务分配记录维护 |
| 排期 | 任务整体日期与成员任务日期分为两层 | 甘特图提供同步/不同步确认 |
| 状态 | 增加测试延期自动判断，取消旧 V4 到样窗口主状态集合 | V5 详设冻结优先级和状态规则 |
| 成果 | 不新增成果提交或验收入口 | 现有历史记录仅作兼容保留，后续是否清理另行批准 |
| 接口/数据 | 需要增量 API/数据兼容设计，不能直接沿用 V4“不改 schema/API”约束 | 实现前另立实现工作包和数据迁移计划 |

本轮设计只定义逻辑数据模型、命令边界和一致性规则，不直接指定物理表的增删改。后续实现工作包必须先对现有 SQLite 数据和 API 做差异盘点，再提交可回滚的迁移方案。

本次修正将 `purpose`、`manual_phase` 和 `color` 冻结为 V5 唯一 canonical 名称，并为五类状态增加固定颜色 token。`test_purpose`、`execution_state` 和 `task_color` 仅作为禁用历史名称被引用，不作为可写字段。

## 5. 范围外与停止条件

范围外：产品代码、数据库迁移、生产发布、AI、手机端、联系人、成果提交、权限系统和云同步。

如果实现需要删除现有表、物理删除历史成果、修改 V2 canonical、或无法保留现有任务编号和事件历史，必须暂停并重新提交变更设计。

## 6. 变更后基线

V5 需求、总体设计、详细设计和追踪矩阵计划组成目标基线 BL-006。完成独立审核并获得人类批准后，才可创建 BL-006 清单并执行激活；在此之前 BL-005 继续是唯一可执行基线。

## 7. 批准门

本变更包及 V5 设计文档当前为 proposed。完成本轮独立审核后，须由人类批准目标基线，随后才能创建实现工作包。
