# 变更包：V4 专题模块信息架构修正

## 1. 变更动机

V3 已具备来源小组、专题、样品池、连续任务、成员、制冷机和成果验收数据，但专题页面存在多个入口、重复列表、抽屉返回路径不一致和分散编辑入口。用户无法形成稳定的“看总览—进入专题—规划样品—安排连续任务—执行—验收”心智模型。

## 2. 当前基线

当前执行基线为 `BL-004`。V4 先以独立权威文档承载，保留 BL-004 中 V1/V2 canonical、V3 schema 3 和 `/api/v3` API 不变；完成文档审核后再生成并审批 V4 目标基线 `BL-005`。

## 3. 拟议变更（V4 Option A）

- 保留六个顶层区域；工作台只做状态总览，专题规划成为专题的唯一管理入口。
- 专题规划采用“专题列表 + 当前专题主工作区”，主工作区提供“概览、样品池、连续任务”三个子页；不再把快速抽屉作为主编辑路径。
- 明确领域层级为“来源小组 → 专题 → 样品池/连续任务序列”；一个任务可绑定多个样品，同一样品可参与同专题多个任务。
- 任务链改为“连续任务序列（人工排序）”，移除前置任务和 `finish-to-start` 的用户可见语义；使用上移、下移或拖拽调整顺序。
- 专题、样品、任务均使用统一的全量编辑事实模型；人工分配和执行中心打开同一个任务编辑器，保存后刷新所有投影。
- 样品编号允许为空，支持后补临时/正式编号；ETA 和实际到样继续保留历史与预览确认。
- 统一测试中、延期、规定时间内到来、规定时间外到来、ETA 未确定和已完成的文字与颜色；到样窗口保留 0～365 天设置，默认 7 天。
- 修复来源小组/制冷机筛选、专题分组、任务选择状态、样品编辑和任务排序入口。
- 暂时移除未落库的“本地联络人”字段；若后续需要持久化，另行提出数据模型变更。

## 5. 范围外与停止条件

范围外：AI 自动生成任务、自动分配人员、手机端、登录权限、云同步、附件托管、V2 canonical 改写、V3 schema/API 破坏性变化、样品级人员绑定和本地联络人持久化。

若实现需要新增字段、迁移、改变现有 API、修改 V2 canonical、改变任务事实归属或引入自动化规则，必须停止当前 V4 任务，重新提交变更设计。

## 6. 批准与验收

本变更已由用户以 `CONF-IA-V4-20260822-01` 确认。V4 文档交付必须通过独立审核；实现前须完成 BL-005 的提议、基线批准和激活。实现验收以 REQ-V4、ARC-COMP-V4 和 QUAL-TRACE-V4 的场景为准。

## 7. 变更后基线

V4 需求、总体设计、详细设计和追踪矩阵将组成目标基线 `BL-005`。在 `BL-005` 完成独立审核、基线批准和激活前，`BL-004` 继续保持唯一 active 基线，V4 文档状态为 proposed；激活后 V4 文档转为 active，BL-004 转为 superseded。
