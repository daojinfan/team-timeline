# CR-002：引入测控计划与人工验收闭环

## 当前基线与状态

- 变更状态：approved，版本 1.0。
- 当前活动基线：BL-002；V1 active 文档和既有能力继续有效。
- 变更后基线：BL-003；本文件不声明其已经激活。
- 开发授权：BL-003 激活前不授权 V2 schema 开发、数据库迁移或产品实现。

## 问题与动机

V1 已提供通用任务、甘特图、负载、日志和备份，但超导量子计算测控组还需要在样品编号未知时承接其他小组需求，提前组织测试项、人员和制冷机，并在到样变化、执行、成果提交和人工验收之间保留轻量且可追溯的上下文。完整实验需求单或自动规划会增加不必要流程，也不符合任务只由人分配的边界。

## 批准变更

- 增加来源小组、对方负责人、我方对接人和轻量测控计划。
- 允许以样品型号提前规划结构化测试项、人工任务、人员、制冷机和到样后任务，到样后再补正式或临时编号。
- 最新预计到样必须是日期或显式“到样时间未定”；计划制冷机必须是具体设备或显式“待定”。
- 预计到样与制冷机可以直接修订，保存前展示影响，保存后自动留历史，不引入繁琐变更单。
- 到样日期改变时，只允许人工选择未开始且到样后执行的任务平移；进行中、完成及未选任务不自动移动。
- 增加默认 7 个自然日且可配置的到样窗口；实际到样未测试时主状态空白，并排除窗口统计。
- 增加人工分配、负载/日期/制冷机冲突提示、成果引用、验收清单和人工通过/退回闭环。
- 以增量 schema 和可恢复迁移扩展 SQLite，同时保持 V1 任务、甘特图、负载、日志、备份及既有 API、CSV、JSON 可用。
- 明确排除 AI、手机端、登录、多用户、云部署和二进制附件托管。

## 迁移、兼容与回滚

- BL-002 明确禁止执行 V2 schema 迁移；只有 BL-003 激活后的授权任务可实施。
- 迁移必须先备份、版本化、增量、事务化并失败停止；不得重置已有 SQLite。
- 现有任务无需关联 V2 计划，原任务、甘特图、负载、日志、备份、API 和 CSV/JSON 格式继续可用。
- 回滚基于应用版本回退和迁移前备份恢复，不能以清空数据库或重置示例数据充当回滚。

## 基线激活门

PM 须先建立并登记正式 V2 文档，创建与最终详设指纹一致的 BL-003，登记并激活它，生成 V2 工作包和上下文路由，并使 Release 治理校验达到 0 error / 0 warning。完成该门之后才可 Plan/Start DEV-A、DEV-B、DEV-C；若权威内容、指纹或范围变化，必须停止并重新评审。
