# CR-002：引入测控计划与人工验收闭环

## 状态声明

本变更包为 **proposed**，尚未获得人类总体设计批准。当前活动基线仍为 BL-002，V1 active 需求与设计继续有效。本变更包不得作为详细设计、数据库迁移或实现授权。

## 问题与变更动机

V1 已提供通用任务、甘特图、负载、日志和备份，但超导量子计算测控组还需要在样品编号未知时承接其他小组需求，提前组织测试项、人员和制冷机，并在到样变化、执行、成果提交和人工验收之间保留轻量且可追溯的上下文。使用完整实验需求单或自动规划会增加不必要流程，也不符合任务只由人分配的边界。

## 当前基线

BL-002。

## 拟议变更

- 面向超导量子计算测控组增加来源小组、轻量测控计划、样品型号与可选编号。
- 允许在到样前规划结构化测试项、人工任务、人员、制冷机和到样后任务。
- 增加预计到样与制冷机的直接修改、影响预览和自动历史，不引入独立繁琐变更单。
- 增加可配置到样窗口和明确的总览状态；删除“已到样待测试”，到样后未测试时主状态空白。
- 增加人工分配台、冲突提示、成果引用、验收清单及人工通过/退回闭环。
- 以增量 schema 和迁移扩展现有 SQLite，保留 V1 能力与既有 API、CSV、JSON 兼容。

## 备选方案与权衡

| 方案 | 结论 | 权衡 |
| --- | --- | --- |
| 继续只用 V1 通用任务 | 不推荐 | 无迁移成本，但来源、到样漂移、制冷机、成果和验收上下文只能散落在描述中，无法可靠筛选和审计 |
| 引入完整实验需求单和强制项目层级 | 不采用 | 结构完整但录入和变更流程过重，不符合轻量计划与可选标签要求 |
| 使用 AI 自动生成计划或分配 | 明确排除 | 可能减少输入，但违反无 AI、任务只由人分配的批准边界 |
| 重建数据库或替换 V1 | 明确排除 | 实现简单但破坏已有数据、接口和用户连续性 |
| 增量扩展并保留 V1（本提案） | 推荐候选 | 迁移和兼容验证更严格，但业务连续性、可回滚性和用户学习成本更优 |

## 迁移、回滚与运行影响

- 迁移原则：先备份、版本化、增量、事务化或可恢复分段、失败停止；不得重置已有 SQLite。
- 兼容原则：现有任务无需关联 V2 计划，原路径和格式继续可用。
- 回滚原则：在详细设计中定义应用回退和迁移前备份恢复，不以清空数据库或示例数据重置充当回滚。
