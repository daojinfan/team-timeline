# 变更包：V5 样品字段收敛

## 1. 变更动机

当前使用场景在样品交付前通常只有型号，规划标签会造成重复填写；实际到样时间也不再作为业务录入字段。表单需要让用户先完成型号、ETA 和备注，交付后再补录样品编号。

## 2. 用户确认范围

- 当前 V5 样品字段只展示和编辑：样品型号、样品编号、预计交付时间、样品备注。
- 样品编号在交付前允许为空；填写编号后用于识别样品已具备可交付标识。
- 移除当前 V5 表单中的规划标签、样品数量和实际到样时间。
- 不建设独立样品库页面；样品仍在任务全量编辑台的任务编辑器中维护。

## 3. 当前基线

当前可执行基线为 BL-007。本变更在用户确认后建立 BL-008，继承既有 V5 三模块实现结果和 WP-011 已验收的数据导入结果。

## 4. 影响分析

| 影响域 | 影响 | 处理 |
| --- | --- | --- |
| V5 任务编辑器 | 样品表单字段减少 | 只展示型号、编号、ETA、备注 |
| 数据/API | 现有规划标签、实际到样列仍被历史数据和旧接口使用 | 保留列和旧接口；V5 新请求自动补兼容值 |
| 状态计算 | 新表单不再维护实际到样日期 | 编号为空作为未具备交付标识，历史到样日期作兼容兜底 |
| V3 旧页面 | 不改变 | 保持历史 UI/API 行为 |

## 5. 变更后基线

BL-008 是本变更的执行基线，包含 V5 需求、总体设计、详细设计、追踪矩阵、CR-008 和 WP-012 路由。实现任务必须在获得独立 execution 批准后启动。

## 6. 兼容与状态规则

- `v5_samples.planning_label`、`v5_samples.arrival_date` 及相关历史接口字段保留，不做物理删除，不作为当前 V5 表单写入入口。
- 新增样品时后端以样品型号生成兼容用规划标签；更新样品时若未传规划标签，沿用或同步为型号。
- 样品交付延期仍由系统读取计算；当前 V5 判断样品编号为空且 ETA 已过的样品为未具备交付标识。历史实际到样字段仅作兼容兜底。
- V3 旧页面和 API 不在本次范围内，避免破坏历史兼容。

## 7. 停止条件

如果实现需要删除历史列、迁移或修改 V3 canonical 接口、增加独立样品导航，必须暂停并重新确认范围。
