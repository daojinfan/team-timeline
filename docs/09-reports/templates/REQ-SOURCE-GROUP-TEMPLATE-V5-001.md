# 小组任务管理与甘特图系统

## 外部小组测试需求提出文档模板

> 适用版本：V5（桌面端）  
> 适用对象：工艺组、读取组、量子门组、电子学组等提出测试需求的小组  
> 使用目的：将外部小组的测试需求整理为测控组可确认、可拆分、可排期的专题、连续任务和样品数据。

## 一、填写边界

本文件先由提出需求的小组填写“需求方填写区”，测控组确认需求后再填写“测控组内部确认区”。

- 文档按“专题建议 → 需求内容 → 样品”组织；一份文档可以包含多组需求内容，每组内容可以包含多个样品。连续任务边界由测控组确认后拆分，不要求需求方预先决定。
- 样品尚未交付时，至少填写样品规划标签、样品型号和数量；具体编号未知时填写 `待定/TBD`。
- 预计交付时间可以是暂定日期；后续变更必须在计划变更记录中保留前后值和原因。
- 制冷机由测控组最终确认；需求方可以填写偏好或限制，但不应把偏好当作最终安排。
- 参与成员、任务颜色、人工阶段、系统状态、甘特图时间由测控组维护，不由需求方填写。
- 本模板不设置联系人、前置任务、任务顺序、每人工时和成果提交字段。

### 3.5 状态维护规则

| 系统状态 | 维护方式 |
| --- | --- |
| 等待样品 | 人工阶段保持“等待样品”，且尚未开始测试。无样品、样品 ETA 待确认、样品未到且 ETA 未过，或全部样品已到但尚未开始测试时，均保持该状态。 |
| 样品交付延期 | 人工阶段仍为“等待样品”，存在已确认 ETA 且当前日期已超过 ETA 的未到样品；ETA 待确认不自动判定延期。 |
| 正在测试 | 由测控组成员手动切换人工阶段。 |
| 测试延期 | 人工阶段为“正在测试”且当前日期超过计划测试结束日期，系统自动展示。 |
| 已完成 | 由测控组成员手动切换，优先级最高。 |

系统不设置“已到样待测试”状态；实际到样日期只作为样品事实记录，任务仍按上述规则展示。

## 四、从需求文档到系统的处理流程

1. 来源小组填写第二部分并提交给测控组。
2. 测控组与来源小组确认需求目的、测试项、样品型号、数量和预计交付时间。
3. 测控组确认专题；没有合适专题时新建专题，暂时无法归类时先放入“无专题”。
4. 测控组根据需求内容拆分连续任务，建立任务记录，并在任务中关联样品集合。
5. 测控组补充制冷机、参与成员、计划测试时间和任务颜色。
6. 执行中心按成员展示甘特图；任务整体时间或成员时间发生调整时，回写任务并记录变更。
7. 样品到样后补充实际到样日期和正式编号；预计交付或制冷机变化时追加变更记录。

## 五、系统录入映射

| 文档位置 | 系统位置 | 说明 |
| --- | --- | --- |
| 2.1 需求基本信息 | 任务全量编辑台 → 来源小组、任务名称、备注 | 需求方填写内容经确认后录入。 |
| 2.2 专题归类建议、3.1 专题确认 | 任务全量编辑台 → 专题管理 | 专题名称、目的、状态和备注由测控组最终确认。 |
| 2.3 需求内容区 | 任务全量编辑台 → 新增任务 | 测控组根据需求内容拆分连续任务，再将测试目的、测试项、样品集合、预计交付和备注写入任务。 |
| 3.2 任务系统属性补充 | 任务全量编辑台 → 全量编辑 | 制冷机、计划测试时间和任务颜色在内部补齐。 |
| 3.3 成员与样品集合关联、3.4 样品级系统记录 | 任务全量编辑台、执行中心 | 参与成员和成员时间由测控组维护；实际到样和正式/临时编号按样品逐行补录，甘特图按成员展示。 |
| 3.6 计划变更记录 | 任务编辑、执行中心 | 先记录前后值和原因，再同步修改系统。 |
