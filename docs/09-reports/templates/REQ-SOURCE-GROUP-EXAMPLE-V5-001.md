# 小组任务管理与甘特图系统

## 外部小组测试需求提出文档实例

> 说明：以下实例以“工艺组提出 Z4 Readout 样品测试需求”为例，演示一份需求中包含两组需求内容、每组包含多个样品，之后由测控组拆分为两个连续任务的填写方式。`TASK-EXAMPLE-*` 和“成员甲/成员乙”为示例值，正式录入系统时由系统生成任务编号并替换成员。

| 字段 | 示例填写 |
| --- | --- |
| 需求内容名称 | `z4readout（BGA露出）样品测试（至少2个）` |
| 测试目的 | `验证 BGA 露出结构样品的焊接质量、读出通道连通性和基础 Q 值，判断是否满足后续测控使用要求。` |

| BGA 通断验证 | 验证 BGA 相关通道的连通性和引脚对应关系。 |
| 读取设计验证 | 验证样品与现有读出设计的适配性。 |

### 2.5 当前系统状态示例

以 2026年08月25日、样品均未到样为例：

| 任务 | 人工阶段 | 当前展示状态 | 状态原因 |
| --- | --- | --- | --- |
| `任务-A` | `等待样品` | `等待样品` | 预计交付日为 2026-09-04，当前尚未超过 ETA。 |
| `任务-B` | `等待样品` | `等待样品` | 预计交付日为 2026-09-08，当前尚未超过 ETA。 |

本例中，即使样品全部到样，只要还没有开始测试，任务仍保持“等待样品”。无样品、样品 ETA 待确认或 ETA 尚未到期时也保持“等待样品”；只有已确认 ETA 已过且仍有样品未到样，才自动显示“样品交付延期”。开始测试后由成员手动切换“正在测试”；超过计划测试结束时间仍未完成时自动显示“测试延期”；测试完成后手动切换“已完成”。系统不设置“已到样待测试”。

## 三、系统录入结果示例

| 文档信息 | 系统录入结果 |
| --- | --- |
| 来源小组 | `工艺组` |
| 专题 | `Z4 Readout 封装与读出验证` |
| 连续任务 | `任务-A：BGA露出`；`任务-B：Wirebonding露出（有Spacer）` |
| 样品 | `BGA-EXP-01、BGA-EXP-02、WB-SP-01、WB-SP-02`，编号均暂为 `待定/TBD` |
| 制冷机 | 两个任务初始安排为 `祖4`，如排期冲突则在变更记录中调整 |
| 成员 | 由测控组在任务全量编辑台中维护，并同步到执行中心成员甘特图 |
| 状态 | 当前均为 `等待样品`，由系统按 ETA、人工阶段和测试计划自动展示 |

> 该实例的关键点是：工艺组只提出“要测什么、为什么测、需要哪些样品、何时大致交付”；专题最终归类、任务编号、制冷机、成员、颜色和甘特图时间由测控组确认并维护。
