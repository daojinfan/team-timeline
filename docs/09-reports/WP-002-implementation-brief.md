# WP-002 桌面端 UX 实施简报

> 本简报已登记到 `DOC-REGISTRY.md`，作为 `BL-002` 的实施输入，把已批准的 `REQ-001`～`REQ-007`、`ARC-COMP-001`～`ARC-COMP-003` 和 `DEC-001` 转为实现契约；它不新增产品范围，也不替代任何批准的权威文档。当前基线继续保持原生 HTML/CSS/JavaScript、Node.js 原生 HTTP 与 SQLite。

## 1. 文件责任与跨文件契约

| 文件所有者 | 唯一责任 | 不得做 |
| --- | --- | --- |
| `public/index.html` | 桌面外壳、视图导航、各视图工具栏、任务模态框、详情抽屉和反馈容器的静态 DOM | 写业务判断、改变 API 或复制相同控件到多个视图 |
| `public/styles.css` | 1280×720 / 1366×768 布局、隐藏/打开/忙碌/错误/空状态、抽屉与模态框样式 | 依赖移动端布局才能完成桌面验收 |
| `public/app.js` | 状态、渲染、交互、客户端筛选、智能范围、偏好、API 调用和反馈 | 新增公共 API、修改持久化数据结构或用未转义用户内容拼接 HTML |
| `src/server.js` | 仅把首次创建空数据库时填充的示例日期改为相对当天生成 | 改表、迁移已有库、改变重置示例数据的既有日期语义、改 API 路径/响应结构或 CSV/JSON 格式 |
| `tests/api.test.js` | 完成状态保持、批量完成、个人进度独立、首次新库动态示例日期及既有兼容回归 | 把固定日历日期作为首次新库的示例数据契约 |

冻结 DOM/状态命名如下，三个前端文件以此对接：

- 顶部主操作：`#newTaskBtn`、`#dataMenuBtn`、`#refreshBtn`；数据菜单只导航到维护视图相应区域，模板、导入、导出与备份的实际内容集中在维护视图。
- 主导航沿用 `[data-view]` 与 `#ganttView/#tasksView/#loadView/#logsView/#maintenanceView`；客户端新增并保存 `state.activeView`。
- 每个工具栏使用 `[data-toolbar-view="gantt|tasks|load|logs|maintenance"]`。任何时刻只显示与 `activeView` 相同的一个工具栏；维护工具栏不得含甘特图或批量控件。
- 左栏为 `#memberSidebar`，只含成员浏览/筛选、折叠按钮与新增成员；`#workspaceMain` 承载活动视图。
- 新建任务：`#taskDialog` 内沿用 `#taskForm`、`#templateSelect`、`#memberChoiceSearch`、`#memberChoices`，并新增 `#cancelTaskCreate` 与提交按钮的稳定标识 `#createTaskSubmit`。
- 详情：沿用 `#detailPane`，新增 `#closeDetailBtn`；仅 `activeTaskId` 或 `activeAssignmentId` 有值时加 `.is-open`，关闭或无选中项时 `hidden`，不占主网格列宽。
- 批量栏沿用 `.batchbar`，但只在任务视图且 `selectedTaskIds.size > 0` 时可见；`#batchStatus` 必须包含 `completed`。
- 筛选反馈使用 `#activeFilters` 和 `#filterResultCount`；统计卡用 `button[data-stat-filter="overdue|overlap"]`，不能用不可聚焦的 `article` 冒充操作控件。
- Toast 容器沿用 `#toast`，允许一个可选撤销按钮；`role="status"` 用于普通成功信息，错误信息切换为 `role="alert"`。用户输入必须继续经 `escapeHtml` 处理。

## 2. 桌面外壳与视图状态

页面从上到下固定为：顶部栏、单行五张统计卡、主视图导航、当前视图专属工具栏、两列工作区（可折叠成员栏 + 活动视图）。默认进入甘特图。详情是约 360px 的右侧覆盖抽屉，不是永久第三列；新建任务是最大宽约 720px 的模态框。

在 1280×720 下，顶部、统计卡、导航和工具栏之后必须已经出现活动视图主体的可辨识内容；页面不得要求先滚过新建任务、模板或 CSV 表单。甘特图超宽内容只能在 `.gantt-shell` 内横向滚动。1366×768 下规则相同。

各视图控件严格如下：

| 活动视图 | 可见控件 | 明确隐藏 |
| --- | --- | --- |
| 甘特图 | 粒度、缩放、范围（含“智能”）、今天、只看有任务成员、任务堆叠 | 任务批量栏、任务排序/卡片列表、日志筛选、维护操作 |
| 任务 | 关键词、成员、状态、开始后/结束前、逾期、重叠、清空、排序、卡片/列表；选中后才显示批量栏 | 粒度、缩放、今天、日志筛选、维护操作 |
| 负载 | 周期（当前/未来 7 天/未来 30 天）和成员筛选；基于现有 `stats.member_load` 客户端展示 | 甘特图、任务筛选与批量栏 |
| 日志 | 关键词、日志类型、日期；基于已加载日志客户端筛选 | 甘特图、任务筛选与批量栏 |
| 维护 | 备份、导出、模板、CSV 导入、归档、回收站、清空日志、删除归档、重置示例数据 | 甘特图、任务筛选与批量栏 |

切换视图必须同步导航选中态、唯一工具栏、唯一 `.view.active`、页面标题语义及偏好；刷新后恢复上次视图。成员栏折叠时只收起左列，不影响主视图和详情抽屉。

## 3. 新建任务模态框契约

`#newTaskBtn` 一次点击打开 `#taskDialog`，打开时焦点落在任务名称，关闭后焦点返回按钮。表单顺序固定为：

1. 基本信息：模板、名称、描述。
2. 排期：开始、结束、颜色、状态。
3. 人员与检查项：可搜索成员、检查清单（每行一项）。
4. 固定底部操作：取消、创建任务。

提交沿用 `POST /api/tasks` 及现有字段，不弹二次确认。提交中只禁用该表单的取消/提交和重复打开入口，按钮文案显示“创建中…”；成功后关闭并清空表单、恢复相对当天的默认日期、只刷新一次数据并 Toast；失败时保持模态框、焦点和全部输入，解除禁用，在表单内显示具体错误并发送错误 Toast。模板保存同样取消非破坏性二次确认，且只刷新一次。

## 4. 按需详情抽屉

从甘特条、任务卡或任务列表点击详情时设置唯一活动对象并打开 `#detailPane`。抽屉保留现有任务/个人分配、清单、成员追加和编辑能力，并增加关闭按钮；关闭、切换到不存在的对象或对象被删除后应清除活动 ID 并隐藏。未选择对象时不得渲染占宽的空第三栏。

任务详情、任务卡和任务列表都显示“标记完成”（已完成时不重复显示），并保留编辑、归档、软删除入口。归档或软删除成功后 Toast 提供一次“撤销”：分别调用既有任务归档恢复或软删除恢复接口；撤销失败显示明确错误，不伪装成功。

## 5. 完成与重新打开工作流

- 单项完成调用既有 `PUT /api/tasks/:id`，仅发送 `status: "completed"`；按钮提交中禁用并显示忙碌态。
- 批量完成通过 `#batchStatus=completed` 调用既有 `POST /api/batch/tasks`；不设置结束日期时不得隐式改日期。
- 若任一成员个人进度低于 100%，完成前在操作区显示提示，完成后 Toast 再提示“任务已完成，个人进度保持不变”；提示不得阻止完成。
- 编辑器状态选项为自动、暂停、已完成、取消。打开已完成任务时必须选中 `completed`；提交未改状态时仍发送/保留 `completed`，不得落回 `auto`。
- 重新打开通过编辑器把已完成任务改为自动、暂停或取消；自动继续由现有日期规则解析为 planned/active。
- API 与数据库继续把任务状态和个人 `progress` 分开；完成任务不得写入 `task_assignments.progress`。

## 6. 智能甘特图与空状态

`rangeMode` 新增并首次默认 `smart`，计算只使用当前筛选和关键词命中的个人分配：

1. 有与今天相交的分配时，范围覆盖这些当前分配，并保留现有少量首尾留白。
2. 没有当前分配但有数据时，按到今天的日期距离选择最近分配；范围聚焦该分配并保留相同留白。并列时优先未来，再按开始日期和 ID 保证结果稳定。
3. 当前筛选无分配但系统仍有任务时，不伪装成“完全无数据”：显示“当前范围/筛选无数据”，提供“查看全部任务”和“查看逾期任务”。前者清空结构化筛选和关键词后采用智能范围，后者一次点击启用逾期筛选。
4. 系统确实没有任务时显示“还没有任务”和“新建任务”，直接打开 `#taskDialog`。

手动选择全部、本周、本月、未来 30 天或未来 90 天后按原规则显示并保存；“今天”只滚动到今天（若在范围内），不改用户选择。范围标签始终显示实际起止日。

## 7. 筛选、反馈与桌面偏好

点击“逾期”统计卡一次即启用逾期筛选；点击“重叠”一次即启用重叠筛选，当前活动任务/甘特视图立即反映结果。`#activeFilters` 将每个生效条件显示为可移除标签，`#filterResultCount` 显示匹配任务数；清空筛选必须同步控件、标签、结果和服务端查询。

客户端以版本化单一键 `teamTaskGantt.desktopPrefs.v1` 保存且仅保存：`activeView`、`scale`、`zoom`、`rangeMode`、`taskViewMode`、`taskSort`、`sidebarCollapsed`。初始化时先读取、校验枚举/数值范围再回填控件；损坏、禁用或写入失败的 `localStorage` 静默回退默认值，不能阻断业务。

所有异步写操作需具备空闲/提交中/成功/失败四态，提交中防重复；失败应保留相关表单/筛选状态。归档与软删除用带撤销动作的 Toast；永久维护仍使用批准设计中的强确认，重置继续要求输入 `RESET`，并继续在操作前下载服务端返回的备份。

## 8. 动态示例数据与兼容边界

`src/server.js` 仅在首次创建空数据库时，以服务端本地“今天”为锚点生成四个示例任务及其个人分配日期。相对位置应保持示例语义：至少一个已完成历史任务、一个与今天相交的活动任务、一个未来计划任务，并保留可观察的多人重叠；任务默认日期与对应分配日期偏移保持一致。

动态日期逻辑只作用于首次创建的新数据库。打开已有数据库不得迁移、重写或纠正任何日期；“重置示例数据”继续沿用既有日期语义，本期不把重置路径动态化，其维护入口、`RESET` 强确认和操作前备份要求保持不变。首次新库的状态仍经现有自动/手动规则处理，完成示例保持 `completed`。不得改变 SQLite 表、数据库路径、API 路径/字段、CSV 列、JSON 备份结构或监听范围。

`tests/api.test.js` 至少验证：

- 新空库的示例日期围绕测试运行当天，包含历史完成、当前活动和未来计划语义，且任务/分配日期一致；测试比较相对关系，不写死年份。
- 单项 `completed` 在随后只编辑标题/描述时仍保持完成。
- 批量 `completed` 成功，个人进度原值不变。
- 原有 11 项 API、SQLite/CSV/JSON 兼容回归继续通过。

## 10. 桌面浏览器验收清单

以下清单必须分别在 **1280×720** 与 **1366×768** 执行；浏览器缩放 100%。

- [ ] 首屏已经看到甘特图主体；页面上方没有新增任务、模板或 CSV 长表单；页面级无横向滚动。
- [ ] 五张统计卡保持单行；“逾期”“重叠”可用键盘聚焦并一次点击应用筛选，标签和结果数同步。
- [ ] 五个主视图逐一切换，始终只有一个专属工具栏；日志、维护不出现甘特图、任务筛选或批量栏。
- [ ] 成员栏可折叠/展开且主视图不跳出可视区域；刷新后折叠状态和当前视图恢复。
- [ ] “新建任务”一次点击打开约 720px 模态框；焦点、字段顺序、取消、提交中禁用、失败保留输入、成功单次刷新均正确。
- [ ] 甘特图首次使用智能范围：当前任务优先；仅历史或仅未来时聚焦最近任务；甘特图横向滚动限制在自身容器。
- [ ] 无任务显示“新建任务”；筛选/范围无结果显示“查看全部任务”和“查看逾期任务”，两个按钮执行正确。

- [ ] 粒度、缩放、范围、任务卡片/列表、排序偏好刷新后恢复；损坏的偏好值不会导致白屏。
