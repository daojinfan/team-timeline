# V2 总体设计：测控计划与人工执行闭环

## 1. 批准边界

V2 把现有桌面任务与甘特图工具增量扩展为适合“超导量子计算测控组”的计划、排期、执行、成果和验收闭环。V1 总体架构继续有效，本文不替代 ARC-OVERALL-001。本文属于 BL-003 的已批准输入，但不声明 BL-003 已激活；激活前不授权实施或迁移。

设计原则：

- 人作决定：无 AI，正式任务、人员、日期、改期选择和验收结果均由人确认。
- 轻量入口：以测控计划承载必要上下文，不引入繁琐实验需求单或强制项目层级。
- 到样前可规划：样品型号足以提前建立测试项、任务和资源排期；编号可到样后补录。
- 直接修改但完整留痕：预计到样和制冷机可直接改，影响先预览，确认后自动记录历史。
- 增量兼容：保留 V1 单体架构和全部现有能力；不重置已有 SQLite，不破坏既有 API、CSV 或 JSON。

## 2. 系统上下文与范围

系统继续作为本地单用户桌面 Web 应用运行：原生 HTML/CSS/JavaScript 客户端通过 Node.js 原生 HTTP 服务访问本地 SQLite。V2 不增加 AI、账号体系、云服务、实时协作、新网络信任边界或移动端。

来源小组负责人、我方对接人、提交人和验收人是业务记录，不构成认证身份。成果 URL 与本地路径按文本引用保存，服务不托管二进制文件。

## 3. 领域层级

```text
来源小组
└─ 测控计划（可选项目/课题标签）
   ├─ 样品信息（型号；正式/临时编号可后补）
   ├─ 到样预测、实际到样与确认历史
   ├─ 计划制冷机与资源变更历史
   ├─ 结构化测试项
   │  └─ 人员任务与排期（人工创建、人工分配）
   └─ 成果提交
      └─ 人工验收记录（通过或退回）
```

项目与课题不是强制父实体，只提供可选标签、筛选和分组。来源小组建立业务上下文，测控计划仍可独立归档和查询。

## 4. 六区桌面信息架构

| 区域 | 主要职责 | 与 V1 的关系 |
| --- | --- | --- |
| 工作台 | 测控计划总览、统计卡、关注窗口、筛选/分组、初始/当前到样漂移 | 新增 V2 聚合入口，不取代 V1 甘特图 |
| 测控计划 | 轻量计划、样品型号与可选编号、测试项、联系人和制冷机 | 新增 V2 领域视图 |
| 人工分配 | 主负责人、协作成员、日期、预计工时、负载/日期/制冷机冲突提示 | 复用并扩展 V1 任务/分配语义，最终决定仍由人作出 |
| 执行 | 任务列表、甘特图、个人进度、到样后执行标记和执行状态 | 保留 V1 任务、甘特图和负载能力 |
| 验收 | 成果说明、提交人/时间、URL/本地路径、清单、通过/退回 | 新增人工闭环，不存二进制附件 |
| 管理 | 来源小组、联系人、制冷机资源、窗口偏好、日志、备份、迁移状态 | 保留 V1 日志、维护、备份和恢复入口 |

详细 DOM 契约由 ARC-COMP-004 冻结。1280×720 与 1366×768 是批准的桌面验收尺寸，无手机端验收项。

## 5. 主状态分类器

状态由只读分类器根据事实计算，不把颜色状态写回任务或日期：

1. 人工验收已通过 → **已完成（绿）**。
2. 至少一个正式测试任务正在执行 → **正在测试中（蓝）**。
3. 已记录实际到样且不满足前两项 → **主状态空白**，并排除到样关注窗口统计。
4. 未到样且缺少当前确认到样日期 → **时间待确认（紫）**。
5. 未到样且本地今天晚于当前确认到样日 → **延期（红）**。
6. 未到样且确认到样日在 `[本地今天, 本地今天 + N 个自然日]` → **规定时间内到来（橙）**。
7. 其余未到样且有未来确认日期 → **规定时间外到来（灰蓝）**。

`N` 默认 7，可由本地桌面偏好配置；改变 `N` 只重新分类，不改变初始/当前预计到样、实际到样或任务日期。“已到样待测试”不进入状态枚举，实际到样只是一项日期事实。

## 6. 关键业务流程

### 6.1 建立计划与到样前规划

用户填写来源小组、计划名称、目的、样品型号、最新预计到样、计划制冷机及结构化测试项即可建立轻量计划。最新预计到样必须是日期或显式“时间待确认”，制冷机必须是具体设备或显式“待定”。联系人、项目/课题标签、正式/临时样品编号可折叠后补。正式人员任务仍需人明确创建、排期并分配。

### 6.2 修订预计到样或制冷机

用户直接编辑当前值，系统先展示计划漂移、候选任务变化、人员负载、日期重叠和制冷机冲突。确认后保存新值和不可覆盖的历史。预计到样改变时，仅“未开始且到样后执行”的任务可列为平移候选，默认不平移，用户逐项选择后才按日期差移动；进行中、完成及未勾选任务不自动移动。制冷机变化不自动改任务日期。

### 6.3 到样、执行、成果与验收

实际到样只登记日期和可选样品编号，不自动开始任务。执行继续使用既有任务状态和个人进度。成果提交只保存说明、业务提交人、时间、URL/本地路径和验收清单快照。验收人手动通过或退回：通过生成记录并完成对应工作；退回保留历史和意见，使工作恢复执行。系统不自动验收。

## 7. 组件边界

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| V2 桌面工作台 | 总览查询、统计、筛选/分组、状态颜色和窗口偏好 | 修改业务日期、自动调度 |
| 测控计划服务 | 来源、计划、样品、测试项的一致性 | 人员自动分配、附件存储 |
| 排期与人工分配服务 | 人工任务、负责人/协作者、工时、冲突检测、平移预览 | 绕过人工确认、移动进行中/完成任务 |
| 执行适配层 | 将 V2 计划/测试项关联到 V1 任务、甘特图、负载和进度 | 改写 V1 任务语义或既有接口 |
| 成果与验收服务 | 文本引用、提交版本、清单快照、通过/退回记录 | 二进制托管、自动验收 |
| 历史与审计服务 | 到样/制冷机历史、人工操作与迁移状态查询 | 身份认证、不可追溯覆盖 |
| 兼容与迁移层 | 增量 schema 版本、事务迁移、备份和兼容验证 | 重置已有数据库、破坏性格式替换 |

## 8. 增量数据概念

- 来源小组与业务联系人。
- 测控计划、可选标签和样品身份（型号、临时编号、正式编号）。
- 结构化测试项及其与既有任务的可空关联。
- 初始/当前预计到样、实际到样及确认历史。
- 制冷机资源、计划选择和变更历史。
- 任务主负责人、协作者、预计工时和“到样后执行”属性。
- 成果提交版本、URL/本地路径、验收清单快照与人工验收记录。

现有任务可以不关联任何 V2 计划并继续工作。新增关联默认为可空；现有记录不得被猜测、自动归类或强制回填。表、字段和约束由 ARC-COMP-004 冻结。

## 9. 迁移、兼容与回滚原则

- V2 采用版本化、可重复检查的增量迁移；迁移前生成可恢复备份，并在单个事务中执行。
- 迁移只增加必要结构和可空关联，不重置、删除或批量改写已有成员、任务、分配、日志、模板和检查项。
- V1 页面与任务、甘特图、负载、日志、备份保持可用；既有 API 路径、请求/响应字段和 CSV/JSON 格式不得破坏。V2 接口只增量添加。
- 迁移失败必须停止启动，不得带着部分 schema 继续写入。回滚以应用版本回退和迁移前备份恢复为基础，不能用重置示例数据代替。
- 迁移脚本、schema 版本表、回滚 runbook 和演练证据必须遵守 ARC-COMP-004 与新基线门。

## 10. 安全与数据边界

- 保持本地单用户和现有监听范围，不把联系人、样品信息、URL 或本地路径发送到外部服务。
- 用户文本呈现前转义；URL 协议受白名单限制；本地路径仅作为不可执行文本展示。
- 提交人、验收人和确认人是业务声明字段，不得暗示已经身份认证。
- 数据删除继续可恢复并优先备份；迁移、批量平移和验收状态改变需留审计记录。

## 11. 总体验收

- V2-REQ-001 至 V2-REQ-016 均映射自动化或桌面验收。
- 状态分类覆盖优先级、默认 7 日窗口、可配置窗口、延期、时间待确认、实际到样空白状态和完成覆盖。
- 选择性平移只改变用户勾选的未开始到样后任务，进行中、完成和未勾选任务不变。
- 人工分配不自动指派，冲突只是提示；人工验收的通过和退回形成闭环。
- 使用真实 V1 数据副本验证迁移、行数、关键字段、API、CSV/JSON、任务、甘特图、负载、日志和备份，不能以新空库替代已有库迁移验证。
- 在 1280×720 和 1366×768 验收六区桌面核心路径，无手机端验收项。
