# V4 详细设计：专题工作区、统一编辑器与同步投影

## 1. 状态与路由

客户端维护一个专题事实状态：`selectedTopicId`、`selectedSampleId`、`selectedTaskId`、`returnArea`、`topicTab`、`statusFilter`、`sourceFilter`、`groupBy` 和 `windowDays`。工作台打开专题时设置 `returnArea=workbench`，但路由目标固定为专题规划；关闭快速预览只关闭预览，不改变主工作区。

任何刷新函数都必须从专题详情 API 重新装载 `topic/samples/tasks`，并同步刷新工作台统计、专题列表、人工分配和执行中心的投影。保存成功后清理过期选择；保存失败保留表单值、冲突预览和错误信息。

## 2. 页面组件

### 2.1 工作台

保留状态卡和摘要列表。摘要行显示专题名称、来源小组、主状态、样品数、任务数和当前制冷机覆盖提示；点击行执行“进入专题规划”，不在工作台维护第二套专题详情。

### 2.2 专题规划

筛选栏包含搜索、来源小组、状态、到样窗口、分组和归档；分组支持不分组、来源小组、制冷机和主状态。列表为空时展示“清除筛选”和“新建专题”。当前专题头部提供编辑专题、归档/恢复和当前状态。

三个子页的职责如下：

- 概览：目的、来源、样品/任务计数、状态摘要和最近事件，只做摘要入口。
- 样品池：表格/卡片显示规划标签、型号、编号、当前 ETA、实际到样和状态；每行有编辑样品、补录编号、修订 ETA、登记到样。
- 连续任务：按人工顺序显示任务卡；卡片显示测试目的、测试项摘要、绑定样品、日期、制冷机、成员、工时和状态；提供新增任务、编辑全部、上移、下移和拖拽保存。

### 2.3 统一编辑器

专题编辑器字段为专题名称、来源小组、目的、来源联系人、默认制冷机；不显示未持久化的本地联络人。样品编辑器允许编号为空，区分临时编号和正式编号。任务全量编辑台字段分为：任务基本信息、测试定义、样品集合、排期与制冷机、成员与工时、保存预览；不显示前置任务。

人工分配和执行中心的“编辑”按钮只携带 `taskId` 打开同一编辑器，并在打开前设置 `selectedTaskId`。成员编辑不再依赖页面上一次点击的隐式状态。

## 3. 状态与颜色契约

| 状态键 | 中文 | 颜色 |
| --- | --- | --- |
| testing | 正在测试中 | 蓝色 |
| delayed | 延期 | 红色 |
| arriving_within_window | 规定时间内到来 | 绿色 |
| arriving_outside_window | 规定时间外到来 | 橙色 |
| time_pending | ETA 待确认 | 紫色 |
| completed | 已完成 | 灰绿色 |

窗口输入限制为 0～365，默认 7；颜色不能是唯一信息，必须同时输出文字标签和可访问名称。

## 4. 排序与确认

任务顺序变更使用现有专题任务排序接口，发送当前任务 ID 的完整排列和版本；服务端返回 stale 时恢复未保存顺序并提示重新加载。排序不修改任务日期、成员、制冷机或成果状态，也不创建依赖记录。

## 5. 编辑与同步矩阵

| 写入入口 | 事实对象 | 保存后刷新 |
| --- | --- | --- |
| 专题头部 | topic | 工作台、专题列表、专题头部、任务上下文 |
| 样品池/任务内快速新增 | sample + task_samples | 样品池、任务卡、任务编辑器、状态统计 |
| 样品 ETA | sample + 事件历史 | 样品状态、专题状态、ETA 影响预览 |
| 任务全量编辑 | task + samples + members + cryostat | 任务链、人工分配、执行中心、成果入口 |
| 人工分配/执行中心编辑 | 同一 task 事实 | 同上，不创建私有副本 |

## 6. 错误、焦点与桌面边界

所有 PUT、排序和 confirm 请求失败时保留表单值；冲突必须显示具体对象、字段和人工确认选项。对话框和确认预览使用 Escape 逆序关闭，保存成功将焦点返回触发按钮。1280×720 与 1366×768 下专题列表和主工作区不得产生页面级横向滚动。

## 7. 验证清单

执行任务必须通过客户端语法、既有 API/测试回归、Git 差异范围检查、专题主路径、样品无编号、ETA、排序、分组、状态颜色、跨入口同步、错误保留、焦点和双分辨率验收。
