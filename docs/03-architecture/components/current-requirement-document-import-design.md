# 当前版本需求文档导入设计

## 目标

上传《集成测试组测控任务需求文档》后生成可补充的需求草稿。草稿完成并通过预览确认后，系统在一个事务中创建当前任务、样品和测试项，同时保留原始 Markdown 附件。

## 流程

上传 → 解析 → 缺失项提示 → 集成测试组补充 → 预览 → 确认创建。

上传阶段只写入原始文档和草稿，不创建业务任务。创建阶段重新校验草稿版本和确认令牌，校验失败或资源无法匹配时整笔回滚。

## 数据

`requirement_documents` 保存文件名、类型、大小、SHA-256、正文、上传人和上传时间。

`requirement_drafts` 保存解析结果、规范化结果、错误和警告、草稿状态、版本及创建的任务 ID。状态包括 `parsed`、`needs_completion`、`ready_for_confirmation`、`created`、`failed` 和 `cancelled`。

## 解析规则

第 1 节读取需求方字段：项目、专题、来源小组、任务名称、预计样品交付时间、制冷机安排、测试目的、样品、测试对象和主要测试项。第 2 节读取集成测试组补充：测试周期、准备方式、负责人、成员、限制、交付物和验收标准。

任务开始日期取预计样品交付时间，结束日期按开始日期加测试周期减一天计算。样品 ETA 使用任务预计交付时间；样品编号为“待定”时保存为空。未填写验收标准保存为“待补充”并生成警告。

## 接口

- `POST /api/v5/requirement-documents`：上传并解析 Markdown。
- `GET /api/v5/requirement-drafts/:id`：读取草稿。
- `PUT /api/v5/requirement-drafts/:id`：保存补充信息。
- `POST /api/v5/requirement-drafts/:id/preview`：生成任务预览和确认令牌。
- `POST /api/v5/requirement-drafts/:id/create`：确认并创建任务。
- `GET /api/v5/requirement-documents/:id`：查看原始附件。

## 不完整文档

项目名称、来源小组、任务名称、预计样品交付时间、测试背景、测试目的、样品、测试项和测试周期缺失时禁止创建，并返回字段级错误。负责人未填写、验收标准待补充、接线表或测试大纲待确认时作为警告显示；管理员可以在确认页知晓后继续创建。

## 权限

管理员可以上传、补充、预览、创建和查看附件。普通用户只能查看已创建任务关联的附件和解析结果。
