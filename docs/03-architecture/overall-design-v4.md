# V4 总体设计：专题唯一工作区

## 1. 领域与事实归属

```text
来源小组 1 ── N 专题
专题 1 ── N 样品
专题 1 ── N 连续任务
任务 M ── N 样品
任务 M ── N 人员
任务 1 ── N 成果 ── 0..1 人工验收
```

来源小组和专题提供规划上下文；样品保存型号、规划标签、编号、ETA 和实际到样；任务保存执行日期、测试定义、成员和制冷机；成果保存任务提交时的样品集合快照。任务顺序是人工排序事实，不是自动依赖图。

## 2. 六区桌面信息架构

| 区域 | V4 职责 | 进入专题后的行为 |
| --- | --- | --- |
| 工作台 | 状态卡、摘要列表、提醒 | 点击专题直接切换到专题规划主工作区 |
| 专题规划 | 专题列表、专题编辑、样品池、连续任务 | 唯一完整专题管理入口 |
| 人工分配 | 跨专题任务负载和成员配置 | 打开统一任务全量编辑台 |
| 执行中心 | 执行状态、结构化任务投影 | 打开统一任务全量编辑台 |
| 成果验收 | 成果提交、人工验收 | 从任务快照进入，不复制任务事实 |
| 资源维护 | 来源小组、制冷机、成员、模板 | 不承担专题和任务编辑 |

历史 V2 测控计划位于专题规划的兼容子页，默认不抢占 V4 主路径。

## 3. 专题主工作区

专题规划使用“筛选栏 + 专题列表 + 当前专题”三段式布局。专题列表是完整列表的唯一来源，当前专题内容在主工作区切换三个子页：概览、样品池、连续任务。快速预览可以作为可选辅助，但不能改变主路由、保存事实或产生第二份专题状态。

## 4. API 与数据边界

V4 只重组现有 `/api/v3/topics`、专题详情、专题/样品/任务 PUT、样品 ETA 预览确认、任务排序和成果接口的调用与投影，不新增表、不迁移数据、不改变请求/响应字段的含义。专题默认制冷机仍只是新任务默认值，实际制冷机事实仍在任务。

## 5. 状态聚合

状态由现有样品 ETA、实际到样、任务执行状态、成果验收和窗口值计算。优先级为：正在测试中 → 延期（ETA 已过且未到样）→ ETA 待确认 → 规定时间内到来 → 规定时间外到来 → 已完成；全部样品到样但没有活动测试任务时不新增“已到样待测试”主状态。颜色和文字在工作台、专题列表、样品池和任务卡中一致。

## 6. 兼容与回滚

V2 canonical 和 V3 数据/接口保持不变。V4 先登记独立文档并进入 BL-005，代码实现按独立提交交付；回滚时可回退 V4 前端提交，不需要恢复数据库。若发现需要 schema/API 变化，停止并重新进行变更控制。
