# V2 需求草案：超导量子计算测控组工作流

## 文档状态与边界

本文是基于当前活动基线 BL-002 起草的 V2 候选需求，尚未获得人类批准，不替代 `REQ-BASE-001`，也不授权详细设计、数据迁移或产品实现。V1 的任务、甘特图、负载、日志和备份能力继续以现有 active 文档为准。

V2 面向“超导量子计算测控组”的本地桌面工作。系统不使用 AI；任务与人员分配只由人明确作出。手机端、登录、多用户协作、云部署和二进制附件托管不在范围内。

## 核心名词

- **来源小组**：提出测控需求的其他小组；记录对方负责人和我方对接人，支持线下确认。
- **测控计划**：围绕一批待到样样品组织目的、预计到样、制冷机、测试项和人员任务的轻量工作单元，不是繁琐的“实验需求单”。
- **测试项**：计划内需要执行和验收的结构化测试内容。
- **人员任务**：由人从测试项或计划需要出发创建并明确分配的正式执行任务。
- **项目/课题标签**：可选的检索与分组标签，不构成“项目→课题→计划”的强制层级。

## 自动主状态与颜色

主状态是总览中的单一分类，不替代任务执行状态或验收记录。判定按以下优先级自上而下执行：

1. **已完成（绿）**：计划要求的成果已人工验收通过。
2. **正在测试中（蓝）**：尚未完成，且至少一个正式测试任务正在执行。
3. **已到样但尚未测试（主状态空白）**：已记录实际到样日期，但没有正在执行的测试任务；不创建“已到样待测试”状态，也不计入任何到样关注窗口统计卡。
4. **时间待确认（紫）**：未到样，且没有有效的当前最新确认到样时间。
5. **延期（红）**：未到样，且本地今天已晚于当前最新确认到样日期。
6. **规定时间内到来（橙）**：未到样，预计到样日在本地今天至“今天 + 关注窗口天数”的闭区间内。
7. **规定时间外到来（灰蓝）**：未到样，预计到样日在关注窗口之后。

记录实际到样日期只改变到样事实和上述分类，不自动开始任务、不自动分配人员、不自动修改排期。若计划完成或开始测试，以更高优先级状态覆盖空白状态。

## 日期与确认规则

- 计划创建时必须为“最新预计到样”填写日期或显式选择“时间待确认”；首次填写并确认日期时保存“初始预计到样”，后续直接修改只更新“当前最新预计到样”，初始值保持不变。
- 总览同时显示当前预计值和相对初始值的提前/延后自然日数；历史记录保留每次确认值及时间。
- 到样关注窗口是用户偏好，默认 7 个自然日；窗口分类使用服务端本地日历日，不能反写任何业务日期。
- 预计到样或制冷机修订的影响预览是保存动作的一部分，不是独立、繁琐的审批单；本地单用户环境下“确认记录”只表达该次人工确认事实，不冒充身份认证。

## 范围外

- AI 生成测试项、AI 分配、AI 验收或自动调度。
- 强制项目/课题层级、完整实验需求单或独立变更单流程。
- 自动平移进行中/已完成任务，或在用户未选择时自动改期。
- 手机端、触摸端专用交互、登录、权限、多用户实时协作、云服务和生产部署。
- 二进制附件存储、同步或版本管理。
- 在总体设计获人类确认之前确定 API 路径、字段级契约、表 DDL、迁移脚本或实施工作包。
