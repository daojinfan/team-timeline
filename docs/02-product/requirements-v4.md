# V4 需求：专题模块信息架构修正

## 1. 范围与原则

V4 面向超导量子计算测控组桌面端使用场景，修正 V3 专题模块的导航、编辑、状态和同步体验。V4 不接入 AI，不建设手机端，不修改 V2 canonical、V3 schema 3 或现有 `/api/v3` 合约。

## 2. 功能需求

- REQ-V4-001：六个顶层区域保持互斥；工作台只做总览，专题规划是专题管理的唯一完整入口。
- REQ-V4-002：工作台点击专题必须直接进入专题规划的对应专题工作区；关闭或返回不应把用户送回一个不可预期的旧抽屉路径。
- REQ-V4-003：专题规划提供来源小组、状态、制冷机、到样窗口、归档和搜索筛选；分组选择必须实际改变列表呈现。
- REQ-V4-004：专题工作区提供概览、样品池、连续任务三个子页；完整专题列表不在工作台和专题工作区之间重复维护。
- REQ-V4-005：专题编辑器维护名称、来源小组、目的、来源联系人和默认制冷机；未持久化的本地联络人不得以可编辑字段出现。
- REQ-V4-006：样品编辑器维护规划标签、型号、可选临时/正式编号、初始 ETA、当前 ETA、ETA pending 和实际到样；编号为空时可以保存。
- REQ-V4-007：样品池提供编辑样品、补录编号、修订 ETA 和登记到样入口；ETA 修订继续经过预览确认并保留历史。
- REQ-V4-008：连续任务页面显示任务顺序、绑定样品、测试目的、测试项、排期、制冷机、成员和预计工时；任务全量编辑台是唯一完整编辑器。
- REQ-V4-009：任务顺序只表示人工连续任务序列；支持上移、下移或拖拽保存，不显示或编辑前置任务和 `finish-to-start` 依赖。
- REQ-V4-010：人工分配和执行中心可以打开同一个任务全量编辑台；保存后所有专题和任务投影同步刷新。
- REQ-V4-011：专题、样品和任务状态使用统一文字和颜色：正在测试中、延期、规定时间内到来、规定时间外到来、ETA 待确认、已完成；全部样品到样但尚未开始测试时不强制显示“待测试”主状态。
- REQ-V4-012：到样窗口支持 0～365 个自然日，默认 7 天；筛选值在桌面端刷新后保持，且不得改变样品事实数据。
- REQ-V4-013：专题、样品、任务任一入口保存后，工作台状态卡、专题列表、任务链、人工分配、执行中心和成果验收读取相同最新事实。
- REQ-V4-014：1280×720 和 1366×768 下页面无级联横向溢出；对话框、确认预览和错误信息满足键盘焦点闭环。

## 3. 非功能与范围边界

V4 必须保持人工创建、人工分配和人工验收；不自动生成任务、不自动分配人员、不自动因实际到样启动任务。所有新增交互必须复用现有 V3 预览确认、版本和冲突处理语义。

## 4. 验收原则

验收至少覆盖：工作台到专题规划主路径、专题编辑、无编号样品、ETA 修订、任务多样品绑定、人工排序、统一任务编辑器、来源小组/分组筛选、状态颜色、跨入口同步、错误保留、焦点闭环和双分辨率无溢出。
