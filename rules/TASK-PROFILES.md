# 任务治理档位

任务档位用于让治理成本与风险相匹配。档位不改变规则优先级、权限边界或必须由人类批准的事项，也不能用来绕过变更控制。

`governance.json.task_profile` 记录项目默认档位，新项目统一默认为 `Release`，`validation_level` 也默认为 `Release`。每个任务开始时都要声明实际采用的档位；只有满足较低档位的全部条件时才可显式指定为 `Standard` 或 `Lite`。发生不确定性时保持 `Release`。

各档位默认上下文软预算由 `governance.json.context_policy` 配置：Lite 为 10,000/14,000 字符、Standard 为 16,000/24,000 字符、Release 为 32,000/48,000 字符（软目标/告警阈值）。字符数是避免绑定特定模型 tokenizer 的可复现代理指标，不等于精确 token 数。这些数值用于发现无关或重复输入，不是质量上限；必需文档、批准、风险、验收标准和验证约束不得因超预算被静默省略。

## 1. Lite

适用于：

- 只读查询、解释、检索和不改变外部状态的诊断；
- 修改范围明确、局部、可逆，且不改变已批准需求、架构、公共接口、数据模型、安全策略或发布行为的工作；
- 不涉及跨模块协调、生产环境、敏感数据、迁移或不可逆操作。

Lite 不要求为纯只读任务创建工作包。涉及文件写入时，仍需有可识别的任务范围和当前基线，不得修改规范性文档或越过已有所有权边界。

开始前至少在内部检查并记录以下信息；默认不向用户打印固定模板，只有 `READY: no`、需要批准或用户要求审计详情时才展示：

```text
GOVERNANCE_PREFLIGHT
PROFILE: Lite
MODE: SINGLE_TASK/TEAM_PROJECT
BASELINE: BL-NNN
SCOPE: <只读范围或允许修改的局部范围>
LITE_JUSTIFICATION: <为何不改变受治理契约或外部状态>
READY: yes/no
```

完成时由 AI 以简洁自然语言报告实际读取或修改的范围、验证结果、发现的风险，以及是否需要提升到 Standard；详细字段保留在机器状态中。

## 2. Standard

这是新项目和普通写入任务的默认档位。适用于：

- 代码、测试、配置或规范性文档的常规修改；
- 需要工作包、依赖、基线、权威文档和验收标准的任务；
- 可能影响其他模块，但不直接执行发布或不可逆操作的任务。

Standard 使用 `AI-EXECUTION-PROTOCOL.md` 中的完整 Preflight 和完成记录，并将其固化到 TASK 契约、状态和证据；不要求把固定格式逐项打印给人类。修改已批准契约时，必须先走变更控制并生成新基线。

## 3. Release

适用于：

- 生产部署、正式发布或用户验收；
- 数据迁移、删除、批量写入或其他不可逆操作；
- 安全、隐私、合规、权限、密钥或质量门禁例外；
- 失败会造成重大业务、数据或运行影响的操作。

Release 在 Standard 要求之上还必须具备：

- 针对本次操作的结构化人类批准；
- 已激活基线、完整验证证据和可追踪版本；
- 备份、回滚或明确说明为何不可回滚；
- 目标环境、执行窗口、观察指标和停止条件；
- 发布后验证及异常处置负责人。

这些控制必须写入 TASK 契约的 `release_controls`，分别记录 `target_environment`、`execution_window`、`rollback_plan`、`observation_metrics`、`stop_conditions` 和 `post_release_owner`。缺少任一字段时 `Plan` 必须失败。Release 即使没有其他风险标志，也必须获得绑定 TASK 契约和明确用户确认引用的 execution 批准。

Release 完成前，编排器必须自动运行 Release 级治理校验；启动前仍运行 Strict，避免把尚未完成的发布证据当成启动前置条件。批准设计或批准开发不等于批准生产发布或不可逆操作。

## 4. 档位升级条件

执行中出现以下任一情况时立即暂停相关写入并提高到 Standard 或 Release：

- 范围超出原声明；
- 发现权威文档冲突、过期基线或所有权不明确；
- 需要改变架构、接口、数据、安全、合规或发布行为；
- 需要访问生产系统、敏感数据或执行不可逆操作；
- 现有验证无法证明风险已受控。

不得为了减少报告、校验或批准步骤而选择 Lite。

编排器和 Strict 校验器执行最低档位门禁：范围、成功标准、总体架构和公共接口风险至少使用 Standard；数据模型/迁移、安全隐私合规、质量门禁例外、生产发布和不可逆操作必须使用 Release。显式批准只授权风险动作，不会降低最低档位。
